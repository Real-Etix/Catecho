# Lifetime Codex totals

The user requests total tokens for each chat since it started. The chat picker will list lifetime totals and include old, inactive sessions. A TOTAL detent will show the selected chat's lifetime input + output on the radio and tucked preview. SEC/MIN/HR retain their current behavior; the chart in TOTAL remains explicitly labeled recent 24-hour activity. Cached input and reasoning remain subsets, not extra tokens.

Keep the existing bounded 24-hour event cache for charts. Add an actor-owned SQLite ledger containing only numeric usage, opaque response/session identifiers and timestamps. Unique response identifiers prevent duplicate counting across polling, archives and restarts. Cumulative legacy records retain the existing conservative delta/reset and child-inheritance rules. Switching a session to identified response records removes its legacy contributions in both stores. Scan all available plain and Zstandard logs, retaining previously indexed totals if source files later disappear. Optional titles remain memory-only.

SQLite is supplied by macOS. Transactions batch each bounded collector poll. Persist per-session aggregates with the identity ledger, capped at 10,000 sessions and a 256 MiB database; reaching a limit or a storage failure must be visible, never silently wrap or expire totals. Existing numeric cache records seed the ledger before full backfill. Missing, corrupt or unrecorded source history cannot be reconstructed, so the UI says lifetime from available local records and preserves indexing/partial/unavailable status. A failed ledger displays unavailable lifetime data while recent monitoring can continue.
