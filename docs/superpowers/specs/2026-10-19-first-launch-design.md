# First-launch radio setup

Use the existing 350 × 392-point ivory radio housing inside the 374 × 416-point panel. A recessed sage screen presents three steps: topics, language, morning startup. Raised cream buttons and ribbed topic switches match the current radio. A three-position tuning indicator marks progress; the speaker and dial remain visible. Each step scrolls when needed, with navigation fixed below it. Respect Reduce Motion and provide native accessible labels and selection states.

New installations open expanded for setup. AI News, GitHub, and Research are selected initially; research has independent subject choices including AI and physics. Require at least one station and at least one research subject when Research is enabled. Language changes preview immediately within setup; English, Simplified Chinese, Traditional Chinese and System default are available. Save topics and language together on completion, then fetch all enabled stations and show the reading screen. Skip uses the existing/default choices without changing login registration. Interrupted setup returns on the next launch. Existing installations are migrated without showing setup or changing settings. A menu command reopens it without discarding an open settings draft.

Start at login is opt-in and uses SMAppService.mainApp. The control reflects the operating system status, supports unregistering, reports errors, and offers the Login Items pane when approval is required. Require installation in Applications for registration. Registration happens only after an explicit switch action. Completion remains available if login cannot be enabled. The same control appears in rear settings. Recheck status when returning from System Settings. The app still starts tucked after setup and refreshes only while awake/running.

No new backend, tracking, API keys, accounts, or source providers. Preserve the bundle identity and installed app path. Test with isolated preferences, fake login operations and a separate preview bundle; verify a real installed login status separately without deleting the existing login item. Publish an updated beta once checked, following the already-authorized GitHub distribution workflow.
