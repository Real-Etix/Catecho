# Codex station

Add an opt-in Codex station to Catecho's existing dial and topic choices. Scope is all recorded Codex sessions on this Mac, explicitly chosen by the user. Keep the existing 374 × 416-point window, ivory Classic and Flat cases, sage screen, language support, antenna, and settings flow.

The screen shows a large numerical reading and a quiet activity bar chart. SEC shows tokens/second averaged over the last 60 seconds with a 60-second chart; MIN shows the last minute's token total with a 60-minute chart; HR shows the last hour's token total with a 24-hour chart. Label the chart's range independently from the headline's interval. Use the existing mechanical detent control for SEC/MIN/HR, and the existing previous/next buttons to move between these views. Show input/output and cached-input/reasoning subsets in accessible detail/help. Raw total is input + output. The UI says recorded usage on this Mac, includes last-recorded freshness, and distinguishes indexing, idle, missing folder, unreadable logs, and partial history. Never claim exact second-by-second generation, a bill, or account-wide subscription allowance.

Use a dependency-free native incremental collector. Prefer per-response token_usage_record events with stable response IDs when present; older cumulative token_count logs require deltas, baselines and reset handling. Ignore inherited parent history in child rollouts; deduplicate copied/archived sessions and response records. Include compaction usage once when an actual usage record exists, never invent usage from a compaction marker. Keep only numeric usage records and opaque IDs in a bounded 24-hour local history. Do not store prompt/response bodies or read auth credentials. Parse off the UI thread; cap per-poll IO and line buffering, handle partial lines, truncation/rotation and cancellation. Poll appended data promptly, display decay on a one-second clock while visible, and back off while tucked.

Default data root is CODEX_HOME when set, otherwise ~/.codex. Rear settings provide a folder chooser and a clear description; only read sessions/ and archived_sessions/. Monitoring runs only when its station is enabled and setup is complete. Disabling it stops collection. Missing formats (including unsupported compression) are reported rather than silently treated as complete. Existing news fetching, update scheduling, and battery-compartment counts exclude this local station. New installs do not enable local monitoring automatically; enable it for this user's requested feature via the UI after testing.

A separate daemon would add an installation dependency; private active-chat integration would add fragile app-version coupling. The native collector is the selected approach. Official server allowance can be added independently later; this feature does not infer it from token counts.
